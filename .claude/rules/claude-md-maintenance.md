# 지시 파일 작성/수정 상세 기준

## 추가 시점
- 같은 실수를 두 번 했을 때, 사용자가 같은 교정을 반복했을 때, 코드리뷰에서 "알았어야 할 것"이 나왔을 때만 추가한다
- 선제적으로 규칙을 늘리지 않는다

## 위치 선택
- 계획 단계에서 필요한 규칙(도메인 경계, 의존 방향, 공통 금지사항)은 반드시 루트에 둔다. 하위 CLAUDE.md 와 paths rule 은 해당 파일을 읽기 전까지 로드되지 않기 때문이다
- 도메인 규칙이 10줄 미만이면 분리하지 않고 루트 섹션으로 둔다. 한 도메인이 20~30줄을 넘거나 루트가 200줄에 근접하면 분리한다
- 테스트 경로까지 함께 적용해야 하는 규칙은 하위 CLAUDE.md 대신 rules + paths 로 작성한다
- `@path` import 는 정리 목적일 뿐 컨텍스트를 줄이지 못한다. 토큰 절감 목적이면 paths rule 또는 하위 CLAUDE.md 를 쓴다
- 개인 설정은 CLAUDE.local.md 에 두고 .gitignore 에 포함한다

## 작성 방식
- 마크다운 헤더와 불릿으로 구조화한다. 긴 문단 금지
- 규칙에는 가능하면 이유를 한 구절로 덧붙인다
- 사람용 메모(담당자, 배경, 이력)는 블록 레벨 HTML 주석으로 작성한다. 컨텍스트 주입 시 제거된다
- 반드시 실행돼야 하는 동작(커밋 전 lint 등)이나 차단이 필요한 동작은 지시 파일이 아니라 hook / permissions.deny 로 제안한다

## 수정 시 점검
- 수정 전 루트, 하위 CLAUDE.md, .claude/rules 전체에서 중복과 충돌을 확인한다
- 더 이상 유효하지 않은 규칙은 남겨두지 말고 삭제를 제안한다
- 수정 후 파일 줄 수를 확인하고 200줄 초과 시 분리안을 제안한다
